# سه نوع کاربر و احراز هویت

| نوع | دسترسی |
|---|---|
| مهمان | فقط مشاهده‌ی بخش‌های عمومی (خانه، آگهی‌ها، مزایده‌ها، آژانس‌ها، رادار). |
| کاربر (واردشده) | چت، رادار، نشان‌شده‌ها، کیف پول و … ؛ **عملیات پرداختی** (بیعانه، ورود به مزایده، برداشت) فقط پس از تأیید احراز هویت. |
| مشاور املاک | همه‌ی امکانات کاربر + پنل آژانس (ثبت آگهی، مزایده‌ی جدید، درخواست مشتریان، مالی). یک حساب، بدون «حالت مشتری/آژانس». |

- نمایشی: `app/Support/DemoAuth.php` (`$auth` در همه‌ی viewها). پیش‌نمایش: `?as=guest|user|agency` و `?profile=none|pending|approved|rejected` (کلید نقش پایین صفحه هم دارد).
- فیلدهای `$auth` که بک‌اند باید بدهد: `check`, `is_agency`, `agency`, `profile_status`, `verified` (= `profile_status === 'approved'`).
- محدودیت: `Controller::requireVerified()` روی `listings.deposit` و `auctions.entry`؛ بک‌اندکار همین را به میدل‌ور تبدیل کند و روی برداشت کیف پول هم بگذارد. کاربر تأییدنشده به `account.profile?need=1&next=…` می‌رود.
- صفحه‌ها: `account` (حساب من)، `account.profile` (فرم: اطلاعات شخصی، تصویر کارت ملی، سلفی با کارت ملی، شبا و کارت بانکی با اعتبارسنجی در `public/js/account.js`)، `account.profile.save` (POST).
- قواعد سمت سرور: کد ملی ۱۰ رقم با رقم کنترلی، شبا IR+۲۴ رقم (mod 97)، کارت ۱۶ رقم (Luhn)، تصویرها jpg/png/webp تا ۵MB، صاحب حساب = نام کاربر.
- گفتگو: نقش در هر گفتگو تعیین می‌شود (آژانسِ همان گفتگو = `agency`، وگرنه `buyer`).
- مسیر `mode.switch` حذف شد.
