# گفتگوی خریدار ↔ نمایشگاه‌دار

هر گفتگو به یک آگهی وصل است. قوانین سامانه (مرجع: **سرور**؛ `js/chat.js` فقط بازخورد سریع است):

| وضعیت | شماره تماس | لینک/ایمیل/آی‌دی پیام‌رسان | پرداخت/معامله‌ی بیرونی |
|---|---|---|---|
| `pre_deposit` (قبل از بیعانه‌ی همان آگهی) | ممنوع | ممنوع | ممنوع |
| `deposit_paid` | مجاز (هماهنگی بازدید) | ممنوع | ممنوع |

- پیام ممنوع **ارسال نمی‌شود**: پاسخ `422 {error, hit}` (`hit` = `phone | link | offsite`، هم‌راستا با برچسب‌های `/admin/chats`)؛ متن در کادر می‌ماند و هشدار نمایش داده می‌شود. از بار سوم هشدار «در صورت تکرار محدود می‌شوید» اضافه می‌شود.
- پیام‌های قدیمیِ حاوی اطلاعات ممنوع، تا پیش از بیعانه برای طرف مقابل پنهان می‌شوند («این پیام حاوی اطلاعات ممنوع بود…»).
- گزارش: هر طرف پیام طرف مقابل را با دلیل (`contact | offsite | abuse | fraud`) گزارش می‌کند ← در پنل ادمین (`/admin/chats`) به‌صورت `flagged` بیاید.
- تشخیص خودکار نمونه: `$chatCheck` در `routes/chat.php` — ارقام فارسی/عربی، فاصله و خط‌تیره بین ارقام، ارقام به حروف («صفر نه یک …»)، `+98`، شماره ثابت، `@id`، `t.me`، دامنه، ایمیل، «کارت به کارت»، «خارج از سایت». قیمت‌هایی مثل `۹۸۵٬۰۰۰٬۰۰۰` شماره حساب نمی‌شوند. بک‌اندکار می‌تواند قوی‌تر کند (ارسال شماره در چند پیام جدا، تصویر…).

## مسیرها (`routes/chat.php`، `require` در `web.php`)
| مسیر | نام |
|---|---|
| GET `/chats` | `chat.index` |
| GET `/chats/start?listing=ID` | `chat.start` (ساخت/بازکردن گفتگو؛ نمونه: همیشه گفتگوی ۱) |
| GET `/chats/{id}` | `chat.show` |
| POST `/chats/{id}/messages` `{text}` | `chat.send` ← 201 `{message}` یا 422 |
| POST `/chats/{id}/report` `{message_id, reason}` | `chat.report` |

نقطه‌های ورود: دکمه‌ی «گفتگو با نمایشگاه» در صفحه‌ی آگهی (دسکتاپ و نوار پایین موبایل)، منوی «بیشتر» (کاربر و نمایشگاه‌دار). نمایشگاه‌دار هویت خریدار را نمی‌بیند («خریدار ۴۲۰۰۰»).
بلادرنگ: فعلاً ارسال/دریافت با درخواست است؛ برای دریافت زنده WebSocket/polling اضافه شود.
ظاهر: `css/chat.css`، `js/chat.js`، `pages/chat/*`.
